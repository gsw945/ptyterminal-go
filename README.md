# ptyterminal-go

[![Go Reference](https://pkg.go.dev/badge/github.com/gsw945/ptyterminal-go/ptygo.svg)](https://pkg.go.dev/github.com/gsw945/ptyterminal-go/ptygo) [![License](https://img.shields.io/badge/License-MIT-blue.svg)](https://opensource.org/license/MIT)

A Go implementation of the cross-platform pseudo terminal (PTY) library [PtyTerminal](https://github.com/gsw945/PtyTerminal) (.NET/C#): a cross-platform PTY library with usage demos.

**English** | [简体中文](./README_zh.md)

## Project Layout

```
ptyterminal-go/
├── ptygo/                  # Core library (Go module: github.com/gsw945/ptyterminal-go/ptygo)
│   ├── ptygo.go            # Public API: Options / Connection / Start()
│   ├── unix.go             # Unix backend (Linux/macOS/BSD, based on github.com/creack/pty)
│   ├── conpty_windows.go   # Windows ConPTY backend (P/Invoke, based on microsoft/hcsshim)
│   ├── winpty_windows.go   # Windows winpty backend (dynamic DLL loading, based on iamacarpet/go-winpty)
│   └── deps/winpty/        # winpty DLLs (same origin as the C# PtyTerminal)
├── examples/
│   ├── pty-cli/            # Console demo: raw-mode byte forwarding + size sync
│   ├── pty-web/            # Web demo: built-in http + WebSocket + xterm.js
│   ├── pty-web-signalr/    # Web demo: built-in http + SignalR + xterm.js
│   └── pty-session/        # Web demo: pty session management (list/create/destroy/reconnect)
└── go.mod
```

## Quick Start

```bash
# Console terminal
go run ./examples/pty-cli

# Web terminal (WebSocket, default http://localhost:8877, path /terminal)
go run ./examples/pty-web

# Web terminal (SignalR, default http://localhost:8878, hub path /terminalHub)
go run ./examples/pty-web-signalr

# Web terminal (pty session management, default http://localhost:8879, path /terminal)
go run ./examples/pty-session
```

## Building Executables (bin/)

The `bin/` directory at the repository root holds build outputs (ignored by `.gitignore`) and is produced by `go build -o bin/...`. To build all examples:

```bash
# Build all examples into bin/ (`.exe` is produced automatically on Windows)
mkdir -p bin
go build -o bin/pty-cli ./examples/pty-cli
go build -o bin/pty-web ./examples/pty-web
go build -o bin/pty-web-signalr ./examples/pty-web-signalr
go build -o bin/pty-session ./examples/pty-session
```

- Single example: `go build -o bin/pty-web ./examples/pty-web`
- Run a built binary: `./bin/pty-web -addr :8877` (same flags as `go run`, e.g. `-winpty`)
- **Windows + winpty mode** (`-winpty` / `ForceWinPty: true`) requires the winpty DLLs next to the executable:

```bash
# Windows only: copy the winpty DLLs to bin/deps/winpty/ (looked up automatically)
mkdir -p bin/deps/winpty
cp ptygo/deps/winpty/* bin/deps/winpty/
```

> Note: `bin/` is generated by the commands above and is not source code; do not commit it manually. The full winpty DLL lookup order is described in "Windows Backend Selection" below.

Alternatively, use the provided scripts: `build.cmd` (Windows) or `build.sh` (Unix/Git Bash).

## Core API

```go
import "github.com/gsw945/ptyterminal-go/ptygo"

conn, err := ptygo.Start(ptygo.Options{
    Rows: 30, Cols: 80,
    Cwd:  "/home/user",
    App:  "/bin/bash",
    Args: []string{"--login"},
    Env:  []string{"FOO=bar"},      // empty value removes the variable
    ForceWinPty: false,             // force the winpty backend on Windows (ConPTY by default)
})
if err != nil { /* ... */ }
defer conn.Close()

go io.Copy(os.Stdout, conn)   // pty output
go io.Copy(conn, os.Stdin)    // pty input
<-conn.Done()                 // wait for the process to exit
fmt.Println(conn.ExitCode())
```

The `Connection` interface:

| Method | Description |
|---|---|
| `Read/Write` | pty output read / input write (`io.Reader`/`io.Writer`) |
| `Close()` | Releases all resources (idempotent; terminates a child that is still running) |
| `Pid()` / `ExitCode()` | Process ID / exit code (0 while running) |
| `Resize(cols, rows)` | Resizes the terminal |
| `Kill()` | Terminates the child immediately |
| `Wait()` / `Done()` | Blocks until exit / exit notification channel |

## Windows Backend Selection (same rules as PtyTerminal)

| Condition | Backend |
|---|---|
| Windows 10 1809+ / Server 2019+ (default) | **ConPTY** (system API, no extra dependency) |
| Older systems (no CreatePseudoConsole) | winpty (automatic fallback) |
| `ForceWinPty: true` (or CLI `--winpty`) | winpty |

**Ctrl+C with ConPTY**: creating a pseudo console leaves the *host* process ignoring
Ctrl+C, which prevented `0x03` written to the input pipe from becoming a
`CTRL_C_EVENT` in the child. The library now restores the default handler with
`SetConsoleCtrlHandler(NULL, FALSE)` right after `CreatePseudoConsole` (the same
step node-pty/VS Code performs), so Ctrl+C interrupts running programs under
ConPTY. Regression tests cover both ConPTY and winpty.

The winpty DLLs (`winpty.dll`/`winpty-agent.exe`/`winpty-debugserver.exe`) live in `ptygo/deps/winpty/`, same origin as C# PtyTerminal. At runtime they are looked up in this order:

1. Env var `PTYGO_WINPTY_DLL` (full path to winpty.dll)
2. `deps/winpty/winpty.dll` next to the executable
3. `winpty.dll` next to the executable
4. `deps/winpty/winpty.dll` in the current working directory

## Examples

### pty-cli

- Puts the host console into raw mode (Windows `SetConsoleMode` / Unix `termios`) and forwards keystrokes as raw bytes — arrows, function keys, Ctrl/Alt combos and IME input all work
- Auto-syncs console window size changes (500ms polling)
- Skips raw mode when stdin is redirected (pipe/file); bytes are forwarded as-is
- Exit: exit the shell inside the pty normally (e.g. `exit`); Ctrl+C is forwarded to the pty child as a key press

### pty-web

- Built-in `net/http` + [github.com/coder/websocket](https://github.com/coder/websocket), frontend xterm.js (embedded via `go:embed`, no external files)
- Wire protocol identical to the C# PtyTerminal web demos:
  - client -> server, text frame: forwarded to the pty as input bytes
  - client -> server, binary frame: JSON command, e.g. `{"action":"resize","data":{"cols":120,"rows":40}}`
  - server -> client, binary frame: raw pty output
- Flags: `-addr` (default `:8877`), `-winpty` (force the winpty backend)

### pty-web-signalr

- SignalR hub demo based on [github.com/philippseith/signalr](https://github.com/philippseith/signalr) (frontend xterm.js + `@microsoft/signalr`, protocol aligned with C# PtyWeb.SignalR):
  - client -> server: `input(string)` (lower-camel mapped from the Go method `Input`), `resize(cols, rows)`
  - server -> client: `Output(byte[])` (base64 under the default JSON protocol), `Closed(exitCode)`
- Note: philippseith/signalr hub methods **must not take a `context.Context` parameter** (unlike ASP.NET Core conventions; use `h.Context()` instead)
- One hub instance per connection; hub methods may be invoked before `OnConnected` (pty spawn) finishes — `Input` and `Resize` wait for the pty to become ready instead of dropping the call
- Known compatibility handling: the winpty backend has an "input lost when the agent is not ready" quirk; the demo delays the first input by 2 seconds (only with `--winpty`; the ConPTY backend has a readiness gate in the library)
- Flags: `-addr` (default `:8878`), `-winpty`

### pty-session

A coder/websocket based pty session management demo (protocol aligned with C# PtyTerminal's examples/PtySession):

- **Sessions outlive the browser connection**: closing the page keeps the pty running on the server; reopening the page lets you pick a session from the list and resume xterm interaction (each session caches the latest 64KB of output and replays it on attach, solving the "first output lines missing" JoinGroup timing problem)
- **Destruction**: explicit `destroy` by the client, or automatic when the pty process exits (e.g. typing `exit`)
- Protocol: binary frames are JSON commands (list/create/attach/detach/destroy/resize), text frames are pty input, binary frames are output (including replay)
- Flags: `-addr` (default `:8879`), `-winpty`

## Modification Guide

| What to change | Where |
|---|---|
| Default shell (cmd/bash) | `defaultShell()` in `examples/pty-cli/main.go`, `examples/pty-web/main.go`, `examples/pty-web-signalr/main.go`, `examples/pty-session/session.go` |
| Web listen port | launch flag `-addr=:8888` |
| Frontend (colors/fonts/title) | `examples/pty-web/index.html`, `examples/pty-web-signalr/index.html` (re-run `go build` afterwards) |
| Child process environment | `Options.Env` (empty value removes a variable) |
| Initial terminal size | `Options.Rows/Cols` |
| DLL deployment for library consumers | put `deps/winpty` next to the exe or set `PTYGO_WINPTY_DLL` |

## Known Limitations

- **winpty first-input readiness**: the agent can drop bytes written before the shell produces its first output. The library now waits for that first output (or a 2s timeout) before the first `Write`, so callers no longer need a sleep. If a child prints nothing at startup, the first write may still be delayed.

- In a "console-less automated environment" (CI, redirected pipes) this repository is tested as: **winpty backend stable; ConPTY backend has a Go-runtime-related initialization race** (cmd.exe occasionally fails with `0xC0000142` or exits right after printing the banner; interactive real terminals work fine). The ConPTY implementation has fixed three real bugs (double-NUL environment block, COORD passed by value, environment ordering) and includes readiness waiting with automatic retry; for stable automation use the winpty backend (`ForceWinPty: true` / `--winpty`)
- Do not use Go runtime concurrency features inside a child created by `forkpty` (Unix)
